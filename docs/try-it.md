# Try one real task and report what happened

Can a clearer Goal help an agent finish your task without drifting or checking
unchanged work repeatedly? Try it on a small, reversible task you already need.
We are looking for the first **3–5 independent, opt-in reports**, including
unsuccessful attempts. This is a recruitment target, not a current user count.

## A 10–20 minute trial

1. [Install the skill](../README.md#start-in-two-minutes) in your coding agent.
2. Choose one small task with an observable finish and a few acceptance criteria.
   You can also use the [public task-filter starter](../examples/task-filter/README.md).
3. Ask: `Use $goal-instruction-writer in Preview mode for this task: ...`
4. Inspect the scope, checks, stop rules, and next action. Draft the Goal, then
   authorize execution only for your chosen task.
5. [Open a trial report](https://github.com/wu736139669/goal-instruction-writer/issues/new?template=trial-report.yml).

Please report your host/model, skill revision, task, expected result, actual
result, and the check behavior you observed. A short sanitized excerpt is enough.
Tell us if the contract felt too long, repeated tests, stopped too early, or
needed frequent prompting. Failures and confusing steps are useful evidence.

## Share only what you choose

GitHub issues are public. Remove credentials and private code or customer data.
A private task can be described without uploading its source. A report is useful
without praising the skill, starring the repository, or allowing a testimonial.
The form asks separately whether we may quote it. A public issue does not grant
permission to contact you elsewhere.

The maintainer will distinguish independent trials, maintainer examples,
confirmed completed tasks, and unverified reports. Directory downloads, clones,
and views do not establish active users.
